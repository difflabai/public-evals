# Task 1: SOC 2 Type II Readiness Assessment

## Objective

Assess Meridian Health Loop's SOC 2 Type II readiness for the proposed 2026-10-01 to 2027-03-31 review period: define the system boundary and trust-services-criteria scope, map existing controls to the criteria, identify and evidence control gaps, and deliver a prioritized remediation roadmap that gets remediation done before the review period opens.

## Requirements

- Define the system boundary (services, infrastructure, data flows, subprocessors) and justify the trust-services-criteria scope from Meridian's actual customer commitments — cite the contract clause or business rationale behind every category included or excluded.
- Map current controls to every in-scope criterion with a status of implemented, partial, or gap, grounded in the evidence set (exports, tickets, messages, interviews, policies) — not in marketing or prior-report assertions.
- Identify control gaps with specific evidence citations, assign each gap a stable identifier, and resolve conflicts between sources explicitly (say which source you trusted and why).
- Produce a prioritized remediation roadmap (P1/P2/P3) with named owners and sequencing that completes P1 items before 2026-10-01.
- Flag any incident with an unmet or un-assessed customer/regulatory notification obligation, and any customer-facing representation that current evidence does not support.
- Follow the Ledgerline Engagement Standards (sources/engagement/kickoff/ledgerline_engagement_standards.md) for terminology, citation format, vocabularies, and date/number conventions in both deliverables.
- Alongside the two deliverables, submit claims.json containing a key_figures object with these exact keys: misrouted_patient_count (patients who received another patient's message in the March 2026 incident), unmanaged_byod_count (employees working on unmanaged personal laptops), workforce_training_completion_rate (fraction of the active workforce that completed the 2026 security-awareness cycle).

## Deliverables

**Filenames:** `soc2_readiness_report.md`, `controls_matrix.csv`, `claims.json`

### soc2_readiness_report.md

The prose readiness report: system boundary and description, trust-services-criteria scoping with rationale, evidenced gap findings, source-conflict resolutions, and the prioritized remediation roadmap tied to the Type II review period. Written to the Ledgerline Engagement Standards.

### controls_matrix.csv

A machine-readable controls matrix with EXACTLY these columns in this order: control_id, tsc_id, criterion, control_description, status, evidence_reviewed, gap_id, remediation, owner, priority. One or more rows per in-scope criterion; every one of the 38 in-scope criteria MUST appear in tsc_id: CC1.1, CC1.2, CC1.3, CC1.4, CC1.5, CC2.1, CC2.2, CC2.3, CC3.1, CC3.2, CC3.3, CC3.4, CC4.1, CC4.2, CC5.1, CC5.2, CC5.3, CC6.1, CC6.2, CC6.3, CC6.4, CC6.5, CC6.6, CC6.7, CC6.8, CC7.1, CC7.2, CC7.3, CC7.4, CC7.5, CC8.1, CC9.1, CC9.2, A1.1, A1.2, A1.3, C1.1, C1.2. status must be exactly one of: implemented | partial | gap. For rows with status partial or gap, gap_id carries a stable identifier (G-01 style), remediation a concrete action, owner a named Meridian individual, and priority one of P1 | P2 | P3; for implemented rows gap_id/remediation/priority may be empty. evidence_reviewed names the source document(s) relied on. Do not include Privacy (P-series) criteria rows.
