# Eval 6: epistemic access (a calibrated model vs a confounded history)

**Question.** Evals 1-5 give the agent a disclosed spec and deterministic dynamics, enough to rebuild the oracle
from the brief. Eval 6 asks what is left when the missing piece is *information*, not tooling. **D1:** an agent
plans 8 quarters for a subscription business from a 72-quarter history in which the decisive quantity (the sign of a
cross-segment marketing spillover) is at best weakly identified; the aided arm additionally holds a calibrated model
package (the coupling and price signs, noised magnitudes, margins and fixed costs, a latent nowcast and a
simulator). How much realized profit is the package worth? **D2:** how do LLM judges rank candidate plans against a
mechanical ledger signal, when each judge is handed the true engine's projection of every plan and told it is crude?
**D3** (a dispersion gate): do five independent self-supply sessions on byte-identical inputs disagree?

Package: `dbwm/eval6/` (module map in its `__init__.py`; D3 in `dbwm/eval6/d3/`). What changed from the paper's
harness: `change-ledger/eval6.md`. Runs of this package are a **new
series**: a seed-free aided model, a sequestered scoring seed, container isolation, explicit no-plan handling and, in
`v1`, the marketing bound and the disclosed profit accounting.

## The worlds (D1)

Eleven certified public worlds `w1`-`w7`, `w9`-`w12` (`data/eval6/worlds/`; seed 8 failed certification). Each is
a **four-segment** subscription business (`core`, `smb`, `ent`, `growth`): one hub segment whose marketing spills
into the other three segments' demand, with one random sign per world (complement or cannibalize). Demand per
segment is an unobserved AR(1) state plus a shared AR(1) market factor. The 72-quarter history was generated by a
centralized policy that moves every segment's levers with the cross-segment average demand, so in-sample the
levers are nearly collinear and the spillover sign is at best weakly identified (every history carries small
exogenous lever noise, `policy_noise` 0.015; see the certification below); in the 8 held-out quarters the agent sets
levers independently and the sign decides where marketing should go. (`dbwm/eval6/latent_engine.py`,
`dbwm/eval6/gen/make_latent_world.py`; `theta.json` has four segments in all 11 worlds.)

Deliverables (sandbox root): `plan.json` `{"plan": {seg: {"marketing": usd/quarter, "price": multiplier}}}` with
total marketing <= the cap stated in `task.json` and prices in [0.7, 1.3] (clamped), and `claims.json`
`{"projected_held_out_profit", "rationale", "analysis_runs"}`.

## Arms and what each one sees

Both arms: Claude Code builtin tools read, write, edit, bash, glob, grep; **min_isolation CONTAINER** (statistical
analysis needs bash and python; bash is not path-confined, so host runs are non-conforming); no harness-served
oracle (`EVAL.oracle_handlers` is empty: the true-dynamics oracle scores the plan after the attempt and can never be
queried). The first prompt is the full brief, as in the paper; `TASK.md` holds the same text.

**Brief (v1).** Runs stage the paper brief plus two disclosures it lacked (E6-26, E6-25): each segment's gross
margin (4 dp) and fixed opex (2 dp) with "total profit = revenue x gm - marketing - fixed, summed over segments and
quarters" in place of the paper's undefined "total gross profit", and each segment's marketing bound (its maximum in
`history.csv`, which the `v1` scorer applies). Both arms get both. The disclosed strings are listed per cell
(`EVAL.disclosed_values_for`) for the sandbox pre-check and the audit; none is a full-precision answer-key value.
The paper text is `prompt.brief(..., version="paper")`.

| arm (paper name) | public/history.csv, public/task.json, brief | fitted_model.json | simulator | world seed / history parameters |
|---|---|---|---|---|
| `unaided` (self-supply) | yes | no | none (own python) | no |
| `aided` (fitted-model) | yes | `AIDED_v2`: true structure with lognormal(0, 0.08) noise on magnitudes, exact coupling and elasticity signs, latent nowcast (true + N(0, 0.04)), customers, budget | `model_sim.py` + `heldout_sim.py` (held-out horizon only) | **no** (v1 removed them) |
| paper `fitted-model` (not runnable) | yes | `AIDED_v1`: the above plus the true world `seed`, exact `phi`/`psi`/`cust0`, `policy_noise`, `meas_noise` | `model_sim.py` + the full `latent_engine.py` | **yes: replays the true latent path** |

`AIDED_v1` carries the true world seed and the history-only parameters, so with the full `latent_engine.py` beside it
`simulate_history` on the fitted world replays the true latent path, end-of-history market factor included, bit-exactly
(E6-01; `tests/eval6/test_eval6_worlds.py::test_seed_replay_leak_v1_known_and_v2_closed`). The paper's fitted models
stay scorer-side under `private/eval6/worlds/*/AIDED_v1` and are never staged: each world's `AIDED_v2` is its
`AIDED_v1` minus the seed and those parameters (`gen/make_fitted_model.py` `strip_to_v2`). The staged simulator is a
port of the paper's `model_sim.py`; its own default seed (2026) differs from every scoring seed.

**Budgets** (`dbwm/eval6/regime.json`, provisional pending a calibration pilot): `max_turns` 60, wall clock 2400 s
and USD 4.0 as rails, 3 reps per world (a single rep cannot separate within-world spread from the arm effect).

## Scoring

`dbwm/eval6/score_d1.py`. The committed plan is reconstructed, then scored by a Monte-Carlo oracle with the true
parameters from the true end-of-history latent state: 500 paths, profit summed over 8 quarters and 4 segments,
price clamped to [0.7, 1.3] x reference, marketing floored at 0. Gap to M* is against the grid optimum re-scored on
the same paths (common random numbers), so committing M*'s plan scores exactly 0.

| | `paper` (the paper's scorer) | `v1` (release default) |
|---|---|---|
| Monte-Carlo seed | 101 (= the answer-key generator's and the paper's aided simulator's) | private seed (`private/eval6/scoring_seeds.json`; override with `DBWM_EVAL6_V1_SCORING_SEED` for a held-out leaderboard) |
| missing / invalid `plan.json`, no `"plan"` wrapper, unknown segments, non-numeric levers | silently scored as the reference plan; only a missing/invalid file is recorded (`committed_error`) | every fallback recorded (`plan_fallback`, `plan_wrapper_missing`, `unknown_segments`, `nonfinite_levers`); a full fallback is `no_plan` |
| marketing per segment | free (the paper bounded price only) | capped at the segment's maximum in `public/history.csv` (`marketing_bounded`; the raw plan stays in `committed_plan`) |
| marketing over the cap | flagged (`budget_ok`), scored at face value | after the per-segment bound, projected proportionally to the cap, flagged (`budget_projected`) |
| out-of-band raw price | clamped (and listed) | clamped and listed in `raw_price_out_of_band` |
| claims | `Decimal(str(v))`, failures -> None | `dbwm.core.claims` strict reading (`$`, `,`, `~` stripped; units are errors) |

`success` (derived; the paper reported none): the plan's true profit reaches the step-0 target tau, the midpoint
between the best naive heuristic and M* (`private/eval6/certify_scan.json`). `claimed_success`: the agent's own
projection reaches tau; `overclaim` = claimed and not achieved. Gap to M* and tau are against the unbounded grid
optimum under both rulesets; on w7, tau (90.05M) lies above the bounded optimum (80.16M), so `v1` reports success
there as undefined (None), never as a forced failure (`score_d1.V1_TAU_ABOVE_BOUNDED_OPTIMUM`, E6-31).
`details.projection_gap_pct` = projected / true - 1 (formerly `overclaim_pct`): under the paper brief it is a
**profit-definition gap, not calibration**, because the oracle charges margins and fixed costs the unaided brief
never disclosed; the v1 brief pins both.

**Headline: realized-profit uplift.** Per world, (mean aided true profit - mean unaided true profit) / mean unaided
x 100 over reps; pooled mean and median over worlds; world-clustered percentile bootstrap (numpy `default_rng(0)`,
B = 5000) (`dbwm/eval6/contrast.py`). Reports always show **both no-plan policies**: `reference` (a trial that
committed nothing usable is scored as the do-nothing reference plan, which is what the paper's contrasts did)
and `exclude` (such trials are dropped, and so is a world left without both arms). `EVAL.report` adds exclusions by
reason counted before any filtering, per-arm profit / gap / projection gap / flags (marketing bounded, budget
projected, price out of band), and the moat buckets as a description only.

## Step-0 certification

`dbwm/eval6/gen/certify_world.py` (`dbwm eval6-worlds certify`); normative certificate
`private/eval6/certify_scan.json` (12 seeds, 400 Monte-Carlo paths). From the certificate:

- 11 of 12 worlds pass; seed 8 fails because 2 of its 3 spokes have the sign recovered.
- Verified-hard: M* beats the best of four naive heuristics by 9.85% to 31.55%.
- Not identifiable at this sample size, **majority rule**: a world passes when at least 2 of 3 spokes have an OLS 95%
  CI that includes 0 or has the wrong sign. Every spoke's CI includes 0 in 8 of 11 worlds; w4 (`ent`, CI [0.47,
  2.92], wrong sign, t = 2.72), w9 (`core`, sign recovered) and w10 (`core`, sign recovered) each pass with one spoke
  whose CI excludes 0. With the history's small exogenous lever noise (`policy_noise` 0.015) the coupling is weakly
  identified, not unidentified.
- Decision-relevant: acting on a **gamma = 0 (no-coupling) belief** costs 4.36% to 30.70% of M*. The gate does not
  test a flipped-sign belief.
- Moats (gamma = 0 belief gap) per world are in `moat_pct`; w7's is 30.70%.

## D2: judges against a ledger

`dbwm/eval6/d2_signals.py`, `d2_judge.py`, `d2_report.py`. Each judge is handed, per candidate plan, a profit
projection from the true engine (true coupling, elasticities and churn) at the prior-mean latent state; the paper's
prompt told it that projection ignored those effects (E6-12). The ledger and the no-ledger control run the same
true engine, so the ledger is close to the oracle itself (E6-13). D2 therefore measures re-ranking damage under
misleading framing; it cannot isolate the value of private access. Signals are scored by Kendall tau-b against V*
over 16 states, which include the decertified seed 8 and uncertified 54-quarter histories (a `certified` state set
is available).

- **Judge prompt.** `--prompt v1` keeps the paper text; `v2` describes the projection accurately.
- **Penalty weight.** The paper set lambda = 1 by hand; the harness's own `calibrate_lambda` selects lambda = 0
  on 16 disjoint states (E6-28). New offline reports print lambda = 1 and lambda = 0 side by side.
- **Judge isolation.** The judge runs through `dbwm.core.judge` in an empty directory with zero tool use asserted
  (E6-14). A report states only where judge - ledger lies (`d2_judge.verdict_v1`, "no mechanism inferred"); the
  paper's summaries carried a hard-coded verdict string (E6-27).

## D3 dispersion gate

*Gate only; not pooled with D1.* The multi-agent designs D4 and D5 need independent self-supply runs to disagree;
D3 checks whether they do. Five self-supply sessions per world in eight of the eleven certified worlds (w1-w7, w9)
each see eval 6's unaided sandbox and a brief that pins the profit accounting (rounded gm and fixed per segment),
names a probe / partner segment pair and a pinned evaluation plan, and report six figures: the probe's
price elasticity and marketing exponent, the spillover from +10% partner marketing (0 = "not identifiable"), and the
pinned plan's total profit, total revenue and probe end-customers. A world x figure cell agrees when the reports lie
within a tolerance (0.02 for the exponents, 1 point for the spillover, 1% of the median for the forecasts); the
pre-committed kill line (KILL-1) fires at agreement on >= 70% of the 48 cells.

**References** (`dbwm/eval6/d3/score.py`, D3-02). `v1` takes profit, revenue and end-customers from one walk of the
engine's own held-out loop, asserts the walk's profit equals `held_out_profit`, and takes the spillover truth as
`exp(0.1 g) - 1`. `paper` keeps the pilot's references, defects included: a re-walk that is not the engine's (seeds
9001 + k, a decaying factor, a 0.05 floor, a power-law coupling) and `1.1**g - 1`. Agreement does not use the
references; consensus-wrong does.

**Runnable arm (non-canonical; never run live).** `dbwm run --eval dbwm.eval6.d3 --model M`
(`dbwm/eval6/d3/__init__.py`, `EVAL.eval_id` `eval6-d3`): one arm, `self-supply` (`canonical=False`), staged exactly
like eval 6's unaided arm (`public/history.csv`, `public/task.json`) with TASK.md and the first prompt = the `v1` D3
brief, which corrects the pilot's one inaccurate sentence ("into {probe}'s latent demand" -> "{partner}'s marketing
multiplies {probe}'s marketing-to-signups response", D3-01) and says how the session's own plan is scored. Builtins
read, write, edit, bash, glob, grep; CONTAINER isolation; no oracle, no fitted model. Disclosure policy, explicit:
the brief discloses each segment's gm (4 dp), fixed (2 dp) and reference marketing (2 dp) and the probe / partner
names (`EVAL.disclosed_values_for`); a test asserts it carries no full-precision `theta.json` value.

- Per attempt (`d3/score.py` `score_attempt`): the six figures as strict numbers (missing -> `missing_figures`),
  each one's deviation from the references, per-figure confidence and `first_action` as reported, and the session's
  `plan.json` scored with the eval-6 D1 scorer (realized profit, gap to M*, price raises, marketing bound).
  `ScoreResult.success` is None: D3 has no per-attempt success.
- Report (`dbwm report --run`): the gate over the first scored, audit-clean attempt per cell, with n per world and
  figure; a rail hit or a missing figure is a missing report, never a zero; "agree-5" is refused when a world has
  fewer than 5 reports.
- Regime (`dbwm/eval6/d3/regime.json`, provisional): instances w1-w7, w9 (w10-w12 allowed), 5 reps, `max_turns` 60,
  wall clock 2400 s, **no per-attempt USD rail** (a per-attempt dollar ceiling can change behaviour below it, D3-03;
  cap the run with `--max-total-usd`), ruleset `v1`. The lab harness's isolation lesions (27-tool additive
  allowlist, permission mode auto, undeleted sandboxes, shared `/tmp`) are closed by the core (instrument rows D3-01
  to D3-06).

## Running it

```
dbwm sandbox-preview --eval 6 --instance w7 --arm aided        # what the agent sees
dbwm run --eval 6 --model <model> [--reps 3] [--isolation container]
dbwm report --run runs/<id>                                      # writes eval6_report.md (both no-plan policies)
dbwm eval6-d2 signals run --n-states 16 --out d2.json [--state-set certified]   # lambda = 1 and 0 side by side
dbwm eval6-d2 report d2.json                                     # neutral readout (where each interval lies)
dbwm eval6-d2 judge run --model <judge> --offline-report d2.json --out DIR [--prompt v1|v2]   # calls an LLM
dbwm eval6-d2 judge run --judge openai_compat --base-url URL --api-key-env VAR [--pricing IN,CACHED_IN,OUT] \
    --model accounts/fireworks/models/glm-5p1 --offline-report d2.json --out DIR   # any OpenAI-compatible judge (SF-04)
dbwm eval6-worlds make --seed 3 --seed-salt <secret> --data-out D --private-out P              # private split (~90 s per seed)
dbwm run --eval dbwm.eval6.d3 --model <model> --max-total-usd <cap>   # D3 self-supply arm (non-canonical)
dbwm report --run runs/<d3-id>                                   # the D3 gate, n per world
```

The `openai_compat` judge talks to any OpenAI-compatible endpoint (for example Fireworks, base URL
`https://api.fireworks.ai/inference/v1`); in this package it has been tested against a local fake endpoint only.

**Public worlds are a dev split.** `task.json` names world `w<seed>`, and the generator derives the answer key from
the seed, so anyone with this package can regenerate the answer keys of `w1`-`w12` (and the world seed also tells a
model that knows the generator where the history noise came from). A scored leaderboard needs a private split:
`--seed-salt` draws theta from `default_rng([salt, seed])`, uses a salt-derived history seed and an opaque world id
(`p` + 10 hex digits); organizers certify those worlds locally (`dbwm eval6-worlds certify --seed-salt ...`), keep
the salt, the answer keys and the scoring seed private, and score with `DBWM_EVAL6_V1_SCORING_SEED`.

## Limitations

- Container runs were validated with the fake CLI only (no API key or OAuth token on the build machine;
  `tests/integration/test_integration_container.py` runs the aided stub through the shell in the real image); no
  live eval-6 session has been run with this package.
- numpy Generator streams are stable across the numpy 2.x versions tested (2.2.6 on Python 3.10, 2.5.3 on 3.12), but
  not contractually; the world regeneration tests (`tests/eval6/test_eval6_worlds.py`) detect drift. Float sums use
  left-to-right summation so results do not change with Python 3.12's compensated `sum`.
- M* is a grid optimum searched on scoring paths (in-sample), with marketing capped at three times reference, so a
  plan can beat it (a negative gap); gap to M* is a lower bound and the uplift is the headline (E6-15).
- The paper's pre-registration document for D1/D2 is not part of this package; the kill rules quoted in the paper
  are not re-stated here. D1 as shipped departs from its registration: two end arms only, 11 worlds against at least
  20, a smooth profit metric.
- D3's runnable arm has never run live; its regime is provisional (see the D3 section).
