# Instrument changes: eval 3 (generative vs grounded)

What the release package (`dbwm/eval3`) does differently from the private harness that ran the paper's eval-3
sessions. File:line references point into that harness's frozen snapshot (`scripts/bwm_coupled/...`, base
commit 87a3ffac): `coupled_planner.py` (trial runner and prompts), `model_tool.py` (the modeling tool, sha256
`cf41620751d2...ae`), `_model_engine.py`,
`model_tool_selftest.py`, `confirm_report.py`. Ledger ids (E23-Dn, Nnn, Rn, Annx) refer to the research ledger;
"Appendix A" is the paper's correction ledger. Eval 3 runs on eval 2's worlds and scorer, so every eval-2 row
([eval2.md](eval2.md)) applies too; cross-cutting runtime changes (sandbox, `--tools`/`--restricted`, env allowlist,
oracle server, turn budget, outcomes, attempts) are the core rows.

Classes: **(a)** integrity defect fixed in v1; **(b)** stale or wrong documentation corrected; **(c)** documented
limitation that cannot be fixed after the fact; **(d)** port mechanics (no behavioural change intended).
