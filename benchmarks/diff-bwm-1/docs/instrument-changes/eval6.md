# Instrument changes: eval 6 (epistemic access; D1 hindcast and D2 rank-off)

What the release package (`dbwm/eval6`) does differently from the private harness that ran the paper's eval-6
sessions. File:line references point into that harness's frozen snapshot (`scripts/bwm_latent/...`, base commit
87a3ffac plus the uncommitted harness diff). Ledger ids (E6-nn, Ann, Nnn) refer to the research ledger; "Appendix A"
and "v7 entry" name entries in the final paper's correction ledger (2026-10-06). Cross-cutting runtime changes
(sandbox, `--tools`/`--restricted`, env allowlist, container isolation, turn budget, outcomes, attempts, judge
isolation) are described in `core-runtime.md` / `core-analysis.md`; eval-6 rows only point at them.

Classes: **(a)** integrity defect fixed in v1; **(b)** stale or wrong documentation corrected; **(c)** documented
limitation that cannot be fixed after the fact; **(d)** port mechanics (no behavioural change intended).

## Alignment with the final paper (2026-10)

What changed when the package was aligned with the paper's final version (2026-10-06). The `paper` ruleset and the
paper briefs are unchanged. The eval-6 D1 `engine_hash` moves anyway, because it hashes `score_d1.py`, which now also carries the `v1` bound and the field
rename (one hash covers both rulesets).

| id | class | old harness | v1 behaviour | ledger / entry |
|---|---|---|---|---|
| E6-25 | (a) marketing never bounded | Entry 5 clamped price to [0.7, 1.3] and left marketing free, so a plan could put a segment far past the history's maximum marketing multiple, where `exp(gamma (m/ref - 1))` multiplies spoke signups many-fold and the scorer extrapolates. | `score_d1` (`v1`): each segment's marketing is capped at that segment's maximum in `public/history.csv` before budget projection (`bound_marketing`; `marketing_bounded` lists the capped segments, the raw plan stays in `committed_plan`); the v1 briefs state the bound per segment. | E6-26 | (a) profit definition undisclosed | The unaided brief asked for "total gross profit" while the oracle charges revenue x gross margin - marketing - fixed opex; neither the brief nor `history.csv` disclosed margins or fixed costs (the aided `fitted_model.json` carried both). | The v1 briefs (both arms) disclose each segment's gm (4 dp) and fixed opex (2 dp), rounded as D3 rounded them, and define "total profit = revenue x gm - marketing - fixed, summed over segments and quarters".
