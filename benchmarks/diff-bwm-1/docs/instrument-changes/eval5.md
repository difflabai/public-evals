# Instrument changes: eval 5 (consulting oracle) and its ELO twin

What the release package (`dbwm/eval5`) does differently from the private harness that ran the paper's eval-5
sessions. File:line references point into that harness's frozen snapshot
(`scripts/difflab_consulting/...` and `data/difflab-consulting/...`, base commit 87a3ffac plus the uncommitted
harness diff). Ledger ids (E5-Dnn, Nnn) refer to the research ledger; "Appendix A" is the paper's correction
ledger. Cross-cutting runtime changes (sandbox, `--tools`/`--restricted`, env allowlist, oracle server, turn
budget, outcomes, attempts, judge isolation) are described in `core-runtime.md` / `core-analysis.md`; eval-5 rows
only point at them.

Classes: **(a)** integrity defect fixed in v1; **(b)** stale or wrong documentation corrected; **(c)** documented
limitation that cannot be fixed after the fact; **(d)** port mechanics (no behavioural change intended).

Rulesets (E5-49): `as-run` = registry v0.1 + the as-run engine, the scorer that ran the sessions; `paper` = the
scorer behind the paper's final numbers, the same engine with the lab's 2026-10-03 SOLVARA-A-13 fix
(`registry_v0.1-fixed.jsonl`, the "oracle of record"); `v1` = registry v1.0 + the fixed engine, for new runs. Before
2026-10-08 the package called the as-run scorer `paper`.
