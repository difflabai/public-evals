# Instrument changes: core runtime (sandbox, tools, environment, oracle server, budgets, outcomes, attempts, ordering)

These are the cross-cutting changes the release runtime (`dbwm/core/{paths,regime,env,sandbox,canary,stream_json,
outcomes,budget,attempts,runner,container,egress_proxy,sidecar}.py`, `dbwm/core/oracle/`, `dbwm/core/adapters/`
except `openai_compat.py`) makes relative to the private harness that ran the paper's sessions. File:line
references point into that harness's frozen snapshot (`scripts/...`). Ledger ids (Annx, Gnn, Nnn, S11) refer to the
research ledger; "Appendix A" is the paper's correction ledger. Per-eval consequences are in
`docs/instrument-changes/evalN.md`, which point back at these rows.

Classes: **(a)** integrity defect fixed in v1; **(c)** documented limitation; **(d)** mechanics (no behavioural
change intended).

Claude Code behaviours that the fixes rely on were verified against Claude Code 2.1.287 (the version pinned in
`docker/Dockerfile`) on 2026-10-01/02 with short `claude -p` runs: `--restricted` confines
Read/Write/Edit/Glob/Grep to the working directory and drops user/project settings and the operator's CLAUDE.md, but
does not confine Bash; `--tools` sets the exact tool list (`init.tools`); `--disable-slash-commands` empties
`init.skills`; an MCP server given with `--strict-mcp-config --mcp-config` appears as `mcp__dbwm__<op>` in
`init.tools` and its calls reach the per-trial oracle server; `--json-schema` adds one synthetic tool,
`StructuredOutput`. On 2026-10-02 the api_key path was checked with the real 2.1.287 CLI against a local stand-in
for the Messages API (dummy key, `ANTHROPIC_BASE_URL` on loopback, all other egress denied by macOS `sandbox-exec`,
no model call; `tests/core/test_core_cli_fake_api.py`, opt-in with `DBWM_CLI_FAKE_API=1`): `--bare` keeps an
`--mcp-config` server but reduces the builtin tools to Bash/Edit/Read (CR-29); without it the tool list is exact and
`apiKeySource` is `ANTHROPIC_API_KEY`; the bash-limit variables of CR-26 leave `init.tools` unchanged.

## Limits of these fixes

- `host` isolation relies on Claude Code's `--restricted` confinement of its file tools; it is only as strong as that
  flag in the pinned CLI version. Arms with bash never run there (except as `host-unsafe`, non-conforming).
- The subscription `session` auth works only at `host` isolation; the container path needs `ANTHROPIC_API_KEY` or
  `CLAUDE_CODE_OAUTH_TOKEN`. The container path was verified end to end with a scripted test double of the CLI in
  the real image (`tests/core/test_core_container_e2e.py`), not with a live model, because no API key or OAuth token
  was available when it was built.
- The per-trial oracle server binds to loopback on the host; any local process that learns the token could call it.
  The token is never in the sandbox or the prompt, and it is redacted from the attempt directory afterwards (CR-32).
- Only `session` (host) and the fake CLI (container) were exercised end to end with a live model: five real
  `claude -p` sessions at `host` ran clean through the full runner (eval 1, 2, 3 arms). `api_key` was
  checked against a local stand-in for the API (CR-29), and the container API relay (CR-35) with the real CLI talking
  through it to that stand-in, never to the real API. `oauth_token`, Bedrock and Vertex under `container` are
  untested (CR-34).
- The default resource limits of the agent container (4 GiB memory, 512 pids) are not calibrated.
