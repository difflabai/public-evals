# Instrument changes: eval 4 (AA-Briefcase-Lite transfer)

This file lists what the release package (`dbwm/eval4`) does differently from the private harness that
ran the paper's eval-4 sessions.

- **File:line references** point into that harness's frozen snapshot (`scripts/bwm_briefcase/...`, base commit
  87a3ffac plus the uncommitted harness diff). The snapshot's `briefcase_planner.py` and `judge.py` are the
  September 2026 versions.
- **Ledger ids.** E4-nn are the eval-4 reader-map defects. Nnn and Annx are research-ledger ids. "Appendix A"
  is the paper's correction ledger.
- **Runtime changes.** Sandbox, `--tools`/`--restricted`, env allowlist, oracle server, turn budget, outcomes,
  attempts and interleave are covered in the core rows (`core-runtime.md`, `core-analysis.md`). Eval-4 rows
  only point at them.

**Classes.**

- **(a)** integrity defect fixed in v1.
- **(b)** stale or wrong documentation corrected.
- **(c)** documented limitation that cannot be fixed after the fact.
- **(d)** port mechanics, no behavioural change intended.

| E4P-44 | (a) | A failed recalculation was silent, and an install that imports `formulas` but cannot recalculate (its scipy fails to load) looked healthy: the paper had no such check (`checker.py:99-138`). | E4P-45 | (a) | The checker recalculated agent workbooks with `formulas.ExcelModel().loads(path)` (`checker.py:120-125`), which opens every OTHER workbook a formula names: an `xl/externalLinks` part (`[1]Sheet!A1`), an inline `'../dir/[book.xlsx]Sheet'!A1` or absolute reference, a defined name holding one, and `INDIRECT("...")` with a literal or computed string (all verified with formulas 1.3.4). ## Attrition, budgets and the runner

| id | class | old harness (file:line) | v1 behaviour | ledger / entry |
